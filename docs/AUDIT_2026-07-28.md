## 1. SECURITY

**Bottom line:** Auth/authorization is exceptionally well done. No critical app-code vulnerabilities found. A few dependency/config hardening items remain.

### 🟢 What's solid (verified)
- **Every API route guards** (`requireEmployee` / `requireBackOffice`) — all 30 route files checked.
- **Every server action guards** — all `'use server'` exports across 19 files call an `assert*` / `require*` helper before any DB work (verified per-function on the 18-export `admin-editor-actions.ts`, 12-export `bonus-actions.ts`, etc.).
- **IDOR handled correctly** — dual-use endpoints (`payroll`, `attendance`, `checklists`, `jobs`, `jobs/by-date`, `my-jobs`) lock crew to their own `employee.id` via `scopedEmployeeId()` and ignore client-supplied ids. Crew self-service actions re-verify job assignment (`crew_actions.respondToJob`).
- **SQL injection** — the `${table}`/`${cols}` interpolation flagged by the scanner in `materials/admin-actions.ts` + `admin-editor-actions.ts` is safe: names come only from a hardcoded `ENTITIES` whitelist (`prepare()` returns null otherwise); all values parameterized.
- **Cron routes** protected by `CRON_SECRET` Bearer check.
- **OAuth callbacks** (Google, QuickBooks) redirect only to hardcoded internal paths — no open redirect. QuickBooks verifies CSRF `state` against an httpOnly cookie.
- **Secrets** — `.env.local` gitignored, no secret patterns in git history.
- Late-minute/tardy calc is recomputed server-side (can't be spoofed by client).

### 🟡 Hardening (fix this week)
- **`src/lib/db.ts` — `ssl: { rejectUnauthorized: false }`** undercuts the `sslmode=verify-full` in the connection string; the DB TLS cert is not actually verified (MITM risk on the DB link, low in practice on Neon). Prefer passing Neon's CA and `rejectUnauthorized: true`.
- **`xlsx` (SheetJS) — high, no fix available** (prototype pollution + ReDoS). Used at runtime for payroll/import parsing. Mitigated because only back-office users upload spreadsheets, but a malicious `.xlsx` could pollute prototypes. Consider the maintained SheetJS build (`cdn.sheetjs.com`) which patches these, or validate/limit parsed shapes.
- **Outdated deps** — `npm audit --omit=dev` shows postcss/sharp (high, build/image-time) + qs (moderate). Run `npm audit fix`; bump Next (16.1.6 → 16.2.x) clears postcss/sharp.
- **Clerk keys are `pk_test_` locally** — confirm Vercel **production** env uses `pk_live_` (could not verify without dashboard access).

### Not checked (out of scope)
Professional pentest, crypto review, compliance (SOC2/PCI). This is a known-failure-mode audit, not a certification.

## 4. BUGS / CORRECTNESS

### 🟡 Real
- **`LIMIT ${parseInt(limit)}` NaN bug** — `api/jobs/route.ts:24,30` and `api/payroll/route.ts:39`. A request like `?limit=abc` yields `parseInt('abc') = NaN` → SQL `LIMIT NaN` → Postgres error → unhandled 500 (these routes have no try/catch). Fix: `const n = parseInt(limit, 10); if (Number.isInteger(n) && n > 0) sql += \` LIMIT ${n}\`;`

### 🟢 Low / note
- **Most API routes have no `try/catch`.** Next.js App Router still catches the throw and returns a 500 (no stack leak in prod), so this isn't a crash — but DB failures surface as bare 500s instead of friendly JSON. Fine for internal tooling; wrap the export routes if you want graceful messages.
- Money/hours math in `bonus.ts`/`profitability.ts` mostly uses `Number(x) || 0` guards — good. A few aggregate reads (`bonus.ts:440-445`) drop the `|| 0`, but those are `SUM()` results that won't be null in practice.

## 7. SCALE / PERFORMANCE (added 2026-07-28)

**Bottom line:** Fine at today's volume. One real serverless foot-gun; a few queries that grow unbounded over time.

### 🔴 High — fix before real concurrent load
- **DB uses Neon's DIRECT endpoint, not the pooler.** `DATABASE_URL` host is `ep-soft-glade-am17c2qc.c-5…` (no `-pooler`), and `lib/db.ts` creates a `pg.Pool` with the default `max: 10`. On Vercel, each function instance opens its own pool against the direct endpoint — under concurrency this exhausts Neon's connection slots (`remaining connection slots are reserved` errors). **Fix:** point `DATABASE_URL` at the **pooled** endpoint (`ep-soft-glade-am17c2qc-pooler.c-5…`, from the Neon dashboard) and optionally set `max: 5` on the Pool. Verify TLS still validates (it will — same CA).

### 🟡 Medium — grows unbounded over time
- **Queries with no LIMIT** that return the whole table on every load: `SELECT * FROM attendance ORDER BY date DESC` (`api/attendance:38`), `performance_events` (`api/performance-events:10`), `checklist_completions` (`api/checklists:29` — grows fastest: one row per job×crew), and back-office `SELECT * FROM jobs` (`api/jobs:38`). Fine now (81 jobs, 31 people); over a year these return thousands of rows each. Add a date window or pagination.
- **Client-side fetching** on many admin pages (attendance, jobs, payroll, mileage, calendar, performance, damages use `useEffect`+`fetch`). Creates a render→fetch waterfall and no server caching. Fine for ~10 internal users; revisit (server-render or cache) if pages get heavier.

### 🟢 Good
- **36 indexes** on the right columns (`effective_date`, `employee_id`, `job_id`, `week_start`, etc.).
- **No N+1** — `bonus.ts`/`tenure-bonus.ts`/`admin-metrics.ts` batch-fetch then compute in memory; the `.map()`s are pure calculation, not per-row queries.
- Admin hub parallelizes its aggregates with `Promise.all`.

### Infrastructure
- Vercel **Hobby** (cron limited to once/day — already worked around). Neon tier + the pooler switch above are the levers before real traffic.

## 8. ACCESSIBILITY (added 2026-07-28)

- **Color contrast passes AA** — computed the muted gray (`#5A6B78`) on cream (`#FFF7E4`) at **5.16:1**, and on the muted panel at **4.66:1** (AA needs 4.5:1). Primary navy on cream is far above.
